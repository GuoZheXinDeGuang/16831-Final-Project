# RASR: Reachability-Aware Subgoal Repair for Hierarchical JEPA Planning

16-831 (Fall 2026) course project. We add three things on top of a frozen, pretrained
[H-JEPA](https://github.com/kevinghst/H-JEPA) hierarchical planner:

1. **Reachability estimator** `R(z_t, g, H, B)`: probability that the low-level MPC with budget `B` reaches the latent
   subgoal `g` within `H` steps, trained on real low-level executions (kNN, MLP, and a distance-logistic reference).
2. **Reachability-aware subgoal selection (P2):** rerank the planner's unchanged level-2 candidate pool by
   `cost − λ · c_min · log(R + δ)`.
3. **Failure monitoring + local repair (P3):** detect stalls from planner-visible signals, re-solve the subgoal with a
   reachability term and a visited-region penalty, and fall back to full replanning.

Environments: **FourRoom Distractors** (full study), **Visual AntMaze** (full pipeline), **DROID** (limited offline check:
open-loop, real-robot video, no simulator).

Project website (all figures, tables, videos): https://claude.ai/artifact/KjymaNKMpWzEbhYGzqz9ky

## Results (summary)

| | FourRoom | Visual AntMaze | DROID (offline) |
|---|---|---|---|
| H-JEPA 2-level baseline, ours | 86.0% (seed 42); 85.3 ± 1.8% over 3 planner seeds | 36.0% (seed 42); 38.0 ± 2.0% over 3 seeds | Fréchet fidelity 38.46 ± 0.89% |
| paper | 81.3 ± 6.7% | 39.3 ± 3.7% | 38.42 ± 0.94% |
| best reachability predictor, test AUROC | MLP 0.903 (ECE 0.022) | distance logistic 0.853 (MLP 0.777) | distance logistic 0.976 (MLP 0.826) |
| reranking (P2) vs baseline | 84.7% vs 85.3% (3 seeds) | 35.3% vs 38.0%, p = 0.60 (3 seeds) | 37.98% vs 38.31%, p = 0.71; time-aligned label 38.85%, p = 0.78 |
| replan every 5 steps (B2, 2× calls) | 82.0% (seed 42 only) vs 86.0% | 44.7% (+23 / −13, p = 0.13) | — |
| full replan on trigger (B4) | 84.7% vs 85.3% (3 seeds) | 48.0% (+23 / −8, p = 0.01) | — |
| rerank + repair (Ours) | 84.7% vs 85.3% | 26.7% (+12 / −29, p = 0.01) | — (no closed loop) |
| repair without R (ablation) | 88.0% vs 85.3%, p = 0.22 | **54.0% (+33 / −9, p < 0.001)** | — |

Main findings (AntMaze: three planner seeds × 50 official tasks, pooled exact McNemar vs baseline):

- **FourRoom:** reachability is predictable, but no method changes success significantly. Baseline failures are a
  level-2 "corner attractor" (reachable subgoals that make no progress), not unexecutable subgoals.
- **AntMaze:** failures are stalls (the ant gets stuck against walls). The repair *without* the reachability term is the
  only significant gain in the project (54.0% vs 38.0%, ahead at every seed). Adding R hurts (26.7%): the val-selected predictor is close to a distance
  prior, so it pulls repaired subgoals back towards the stuck state and cancels the exploration term. The MLP predictor
  (ablation, seed 42) is less extreme and lands at 38%.
- **DROID:** no effect. The original offline label rewards "the subgoal stays near the start" (90% of positives match
  the first 0.6 s of the expert video), so reranking picks conservative plans that the Fréchet metric does not reward.
  A post-hoc time-aligned label removes that shortcut but still gives no significant change (+0.5 points, p = 0.78).

Full numbers: `results/` (exported summaries) and `docs/IMPLEMENTATION_STATUS.md` (running log of every decision).

## Repository layout

```text

  common.py           config / checkpoint / eval helpers shared by all scripts
  instrument.py       instrumented planner: per-call latents, plans, compute counters
  branch.py           env snapshot / restore and fixed-subgoal level-1 attempts (P1 labels)
  envs.py             FourRoom / AntMaze state adapters
  reachability.py     labels, eps calibration, kNN, MLP, distance-logistic predictors, metrics
  rasr_solver.py      P2 reranking + P3 monitor / repair / fallback (RASRConfig)
  xy_probe.py         analysis-only latent -> xy probe for figures
scripts/              entry points (run_baseline.py, collect_attempts.py, train_reachability.py, compare_methods.py,
                      droid_rasr.py, ...) and launch_*.sh job scripts; build_site.py builds the website
configs/rasr/         method configs (FourRoom); configs/rasr/ant/ AntMaze configs (generated by make_ant_configs.py)
tests/                unit tests and GPU regression tests (bit-reproducibility, snapshot restore, solver)
docs/                 RUN.md (reproduction), IMPLEMENTATION_STATUS.md (log), plan.md (original plan), site notes
results/              small exported result files (summaries, tables, per-episode CSVs, figures)
```

## Setup and reproduction

See [`docs/RUN.md`](docs/RUN.md). In short: clone upstream H-JEPA at commit `97054ec` into `H-JEPA/`, install it in a
Python 3.11 venv, `source activate_rasr.sh`, download the checkpoints and evaluation tasks, then run the `scripts/launch_*`
jobs per environment. Everything was run on one RTX 4090.

Upstream code, datasets and checkpoints are not included (`H-JEPA/`, `hjepa_home/`); raw outputs (`outputs/`, several
GB) are not included either. `python3 scripts/export_results.py` regenerates `results/` from `outputs/`.

## Notes on protocol

- The H-JEPA backbone is frozen. At inference the planner sees only pixels, latents, model predictions and the
  reachability model; simulator state is used for labels and evaluation only.
- Train / val / test are split by start–goal task; thresholds, temperatures, λ and the predictor type are chosen on val.
- Upstream FourRoom resets are unseeded, so `run_baseline.py` seeds every reset; runs are bit-identical across processes.
- Deviations and post-hoc analyses are listed in `docs/IMPLEMENTATION_STATUS.md`.
